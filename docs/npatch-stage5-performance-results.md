# 阶段 5 启动性能实施与证据

本页记录实际实施结果，设计和退出条件见[阶段 5 设计](npatch-stage5-startup-performance-design.md)。5.1 测量与基线、5.2 按需适配已完成，下一步为 5.3 共享准备与进程开销；阶段 5 最终验收尚未完成。

## 5.1 测量边界与环境

2026-10-23，有线机 `13a7a291`，Android 16/arm64，B 站 8.90.2，固定修复版 833、等级 2，Manager/embed 同证书覆盖安装。详细计时仅由 Debug 构建参数 `-PinnocentLab.startupTrace=true` 启用，普通 Debug 默认关闭，Release 固定关闭。查询复用现有签名权限和回调线程，但使用独立 DEBUG action、本次 nonce、安装时间及模块版本校验；不扩展生产 v4/schema 1 或许可协议。

进程内按逻辑 ID 聚合重复调用，每个入口/尝试最多 128 项、最多两次授权尝试；保留包含时间、自身时间、调用/异常次数、线程类别及有界父级 ID。只在明确启动根段内记录共享定位和注册，普通业务回调不持续采样。未完成的段不冒充完成，溢出计数不为零的表不得作为完整归因；测量不落盘，测试在启动结束后显式查询并保存。

本文的“模块同步耗时”为主线程 `entry`（`onPackageReady` 安装 bootstrap）、`authorization`（含许可与安装）和 `application.ready` 根段之和；父子段不重复求和，包含同步等待，不是 CPU 时间。不包含 loader、模块对象构造、宿主 Application 本体或整个首帧耗时。适配提交/同步准备单独计时；后台适配与重绑定沿既有开始/结束日志独立观察，不把重叠的后台时间加进同步总数。若后续要优化后台调度，须补齐该具体任务的单调计时。

默认组将可自动恢复的宿主业务设置恢复为目录默认值，保留账号授权、条款、手动恢复项、模块 UI 与系统设置。组合组在相同基础上开启首页推广过滤、搜索默认词净化、播放器弹窗净化、默认 1080P（QN 80）和 1.5 倍速；自由复制保持默认开启。配置过程为显式测试动作，每轮严格匹配本次完整许可身份；不同组之间派生修订可变化，不用数值 revision 相等代替业务配置一致。

采样期间设置端点因 Instrumentation 存活，不代表强停设置 App 的场景。每轮停止/启动宿主进程，确认首页导航和搜索入口，按当前边界点击搜索并等待输入框响应；首页按 250ms、输入响应按 100ms 轮询，包含固定输入动作开销。失败日志保留，不从成功样本中静默抹掉。系统 Displayed 在测试结束后的短日志窗口中未稳定取得，原 JSON 的 `firstFrameMs` 保持 null；另保存本轮连续的系统/模块日志，不能把首页出现时间冒充系统首帧。

默认配置的主要定位候选包括评论净化、相关推荐、画质、互动浮层及评论拓扑；初次 10 轮观察的包含耗时中位数分别约 227 / 146 / 69 / 58 / 56ms。这些内部的共用反射时间已计入父段，不能再加一次，也不能将各项中位数直接相加承诺收益。后续优先审计关闭能力的定位需求；相关推荐依赖的规则/共享链较多，未完成审计前保持原路径。上述数值均为基线，不是优化收益。

同源码关闭采样后，两种模式各独立预热并测 3 次，均为当前许可、43 Hook、`cache=file-hit`：embed 安装中位数 1786ms，Manager 为 1795ms；主页/搜索响应中位数分别为 14329/15067ms、14445/16234ms，全部通过。详细计时开启时安装基线约 1902–1921ms，说明仍有约 1.8 秒实际安装成本，测量器没有主导该成本；3 次对照不足以把约 0.1 秒差值全归因为测量开销，最终收益仍需关闭采样的候选对照。关闭采样时未返回详细 trace，生产 v4 查询继续有效，没有把无 trace 写成 0ms。

| 边界 | 当前消费者/时序 | 优化约束 |
|---|---|---|
| 评论低/高绑定、原生/Compose 复制、简介复制 | 自由复制及拓扑共享观察；主进程和其它宿主进程均有既有公共 Hook | 保留首次注册和共享依赖，不能仅按拓扑关闭省掉复制绑定 |
| 暂停页、顶栏、画质、评论过滤/净化/拓扑、相关推荐、Story、底栏和组件过滤 | 对应安装器已有主进程门控；部分点在门控前因共享适配求值 | 先核对配置和消费者并集；不把关闭/未探测报成缺失或成功 |
| 首页 Banner、游戏推广、商品及复制公共路径 | 存在未统一限制为主进程的安装代码 | 子进程保留；未完成调用审计前不创建整进程禁用表 |
| 实时适配与文件缓存 | 实时点优先，校验后的缓存补位；后台适配独立写完整结果 | 按需结果仅限当前启动，禁止不完整结果覆盖完整缓存 |
| 主进程、`:web`、`:download`、`:ijkservice` | 各自独立新鲜许可，主进程失败最多一次前台重试 | 不共享许可，不缩短窗口，不用旧授权缓存替代独立取得 |
| 漫游 attach、适配补安装与诊断汇总 | 与业务同步及相对时序有关，不能凭名称判断可推迟 | 先看实际自身占比和首次调用期限，暂不新增后台调度 |

## 5.2 按需适配

仅对实际框架检测为 NPatch 的主进程启用需求投影：13 类已审计的可选定位按当前已获准的不可变配置请求，包含动态标签、完整数字、竖屏控件、互动浮层、PGC 弹窗、状态栏、画质、青少年提示、评论净化/过滤/拓扑/Tab 与开屏。拓扑会保留共享过滤准备；复制低/高绑定始终保留。相关推荐、Banner 等未完成配置依赖审计的路径维持原行为。标准框架、子进程及完整离线定位此单元沿用全量路径。

省略项明确为 `NOT_REQUESTED`，不记缺失或成功；缓存中的 FOUND 不覆盖该状态，也不重新补回被省略字段。`startupExcluded` 是进程内投影标记，投影禁止序列化或被当作可复用缓存，解码也拒绝带未请求状态的伪完整缓存。后台适配仍产出完整结果，原版 DEX 审核、重绑定、重置时间、实时优先及 schema 62/rule 79 保持。启动不计算不完整的全量协议摘要，该项同样明确未请求；设置 App 读取的完整缓存不受影响。

新增 6 项 JVM 行为测试，覆盖各消费者/共享依赖、画质归一、未知需求回退完整定位、缓存 FOUND 不复活省略项、请求项实时优先，以及投影/污染缓存拒绝。首轮仅旧完整摘要的精确格式契约失败，已让 `not_requested=0` 不改变完整结果原格式，保留旧测试；首轮日志 `demand/gates.log` 不计通过。顺带修正了 5.1 计时器 Java ThreadLocal 的空值标注警告，未改变采集范围。
