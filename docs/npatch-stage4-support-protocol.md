# 阶段 4 支持证据协议

运行诊断与激活/许可继续分离。进程查询 v3 在原 v2 字段上增加 `startups` 和 `guardedFailures`；双方只接受当前版本、完整白名单、整数类型、当前宿主更新时间及本次 nonce。旧协议无响应保持未知，不能据此判断未注入或恢复许可。授权和主诊断 schema 3、报告格式 7 均不变。

启动记录每个进程最多 8 份，设置 App 私有原子文件按当前宿主安装和模块版本隔离。只在用户查询后保存实际观察到的记录，同一随机启动 session 合并为最近一次尝试，刷新不增加启动次数；没有访问诊断页的启动不会被追溯补齐。p50 取排序后的下中位数，max/p50 只代表已采集样本。

`admissionMs` 为新鲜授权阶段墙钟耗时，`installMs` 为 Hook 安装链耗时（尚未安装为 null），`totalMs` 仅为这两个阶段之和，不代表整个冷启动或首帧。`attempt` 包括前台重试。通道列表仅包括授权决策前已消费的实际运输结果；未完成、取消及迟到结果不计为失败，也不冒充全面成功率。配置来源沿用当前回执，选中的运输通道单独展示；同进程 local 也执行原 UID/nonce/租约校验。

后续崩溃/Media 日志采用独立、有界的支持附件协议，通过签名权限和随机 nonce 查询。附件只传白名单提取结果，不向主诊断 JSON 填入任意日志。导出包将包含原报告、补丁参数、实际进程/样本、独立脱敏附件及明确的缺失状态；不纳入偏好值、凭据或原始日志。版本漂移观测也只用于支持提示，不得将旧版本运行信息当成当前激活回执。
