# 阶段 4 支持证据协议

运行诊断与激活/许可继续分离。进程查询 v4 在原 v2 字段上增加 `startups`、`guardedFailures` 和 `support`；双方只接受当前版本、完整白名单、整数类型、当前宿主更新时间及本次 nonce。旧协议无响应保持未知，不能据此判断未注入或恢复许可。授权和主诊断 schema 3、报告格式 7 均不变。

启动记录每个进程最多 8 份，设置 App 私有原子文件按当前宿主安装和模块版本隔离。只在用户查询后保存实际观察到的记录，同一随机启动 session 合并为最近一次尝试，刷新不增加启动次数；没有访问诊断页的启动不会被追溯补齐。p50 取排序后的下中位数，max/p50 只代表已采集样本。

`admissionMs` 为新鲜授权阶段墙钟耗时，`installMs` 为 Hook 安装链耗时（尚未安装为 null），`totalMs` 仅为这两个阶段之和，不代表整个冷启动或首帧。`attempt` 包括前台重试。通道列表仅包括授权决策前已消费的实际运输结果；未完成、取消及迟到结果不计为失败，也不冒充全面成功率。配置来源沿用当前回执，选中的运输通道单独展示；同进程 local 也执行原 UID/nonce/租约校验。

后续崩溃/Media 日志采用独立、有界的支持附件协议，通过签名权限和随机 nonce 查询。附件只传白名单提取结果，不向主诊断 JSON 填入任意日志。导出包将包含原报告、补丁参数、实际进程/样本、独立脱敏附件及明确的缺失状态；不纳入偏好值、凭据或原始日志。版本漂移观测也只用于支持提示，不得将旧版本运行信息当成当前激活回执。

崩溃附件 schema 1 的状态为 NOT_QUERIED / AVAILABLE / EMPTY / UNAVAILABLE / INVALID，异常仅包含时间、固定类别、是否观察到模块栈及最多 8 个白名单类/方法/行号。异常消息、线程名、源文件名、任意业务文本一律不传。模块栈存在只是一条线索，缺失也不能排除模块（R8、混合栈、记录截断及 handler 安装时点均有限制）。native 信号、ANR 与安装前崩溃不在此 Java handler 覆盖范围。

宿主每进程私有目录保留 3 份、单份上限 32 KB；正常启动不读写这些文件，查询在既有诊断线程读回。handler 链始终交还原线程与原 Throwable；落盘失败也不吞异常。同一异常链嵌套包装只记录一次，宿主替换默认 handler 后在查询时重新接入其最新链。设置 App 的启动历史不保存这些附件。

仅显式支持包采集读取主进程 externalMediaDirs/npatch/log 的最新日文件尾部至多 64 KB、最多末 200 行，输出至多 40 个白名单事件/栈位置。原正文、异常消息、路径、URL、账号和令牌均不输出；EMPTY 表示没有可提取证据，不证明没有崩溃。此协议最多 16 进程/128 Ki 字符，不读取任意传入路径或整份日志，不申请所有文件访问。DEBUG 诊断页的明确测试按钮及显式 opt-in instrumentation 可以构造一次主进程 Java 崩溃，Release 不接受此动作。
版本漂移使用同一 v4 查询取得本次版本观测，但版本不一致时只保留排序去重的版本码，不将旧/混合版本进程、native 或功能统计传给当前进程展示。原严格 query 继续拒绝版本不一致；主激活与许可完全不依赖此观测。历史已确认版本及时间与本次响应分别展示。更早协议没有兼容响应时保持未知，不推断实际版本；同版本码不替代内嵌 APK 内容校验。Manager 恢复入口只通过已验证的显式应用启动封装解析。

健康度以最近 8 次已采集启动的最后一次尝试为样本。四路通道比率为“已收结果中的授权取得数 / 已收结果数”，零分母显示未知；它不是所有尝试、未完成请求或全部冷启动的成功率。安装耗时为 null 的样本不进入 p50/max，但仍计入已观测启动与授权结果。Manager 可达性由显式诊断工作线程复用有界 Provider 查询，与作用域、配置来源、宿主授权分别展示；embed 不访问 Manager。通用诊断/自动遥测不主动执行此体检。
