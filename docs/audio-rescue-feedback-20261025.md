# 人声增强听感与圆角裁切修订

2026-10-25，继续在 `experiment/audio-enhance` worktree 开发。用户指出音频弹窗描述被圆角裁掉，并反映开启人声增强后浑浊、不通透。测试集用于开发回归，原先的指标页并不适合作为普通用户的操作界面；本轮另外提供同一实际视频的简单三版试听。

## 原因与修改

原实现把干声也放在 16 kHz 重采样路径内，90% 模型输出加 10% 干声仍然无法保留原始高频。固定集的讲话源大多本来就是 16 kHz，因此此前的 SI-SDR/STOI 改善没有覆盖这项音色损伤。

人声增强现在采用 `延迟后的全频原声 + 0.7 × (模型低频输出 − 同路径低频原声)`。原声不再整体经过低通；48 kHz 的延迟仍为 1582 帧，分数延迟采样率使用四点插值，所有新缓冲均参与部分写入回滚。没有用高频均衡器强行抬升已丢失的细节。模型仍可能改变低频段音色，不能保证主观自然度。

全面保留高频也会放回宽带底噪，因此单独的“语音降噪”保留原有 75% 处理量及窄带抑噪路径；“人声增强”使用较温和的 70% 修正量并保留高频。两项同时开启只运行一次人声增强路径。这是两个不同取舍，不能声称原声保留与强抑噪可以同时无损实现。

音频弹窗正文为 Lumen 圆角回弹视口增加左右 12 dp、上下 14 dp 内边距，保持原有圆角与滚动能力；未修改公共弹窗裁剪。三种语言同步精简文案，明确自动补耳的实际范围。

自动补耳只在持续约 200 ms、两耳能量差超过约 24 dB 且正常一耳足够可闻时接入；能够补持续单耳无声或近似缺声，不会普遍拉平正常立体声或一般左右音量差。需要强制双耳一致时已有“左右混合为单声道”，同时提示反相抵消风险。本轮没有偷偷扩展自动均衡语义。

## 用户实际视频

从用户当时手机页面确认穷数码 CHANNEL 的 `BV1VKpR6TE6e`：《5000块钱玩RTX4090？？？可惜是个M「穷数码」》。暂停点为 75.952 秒。本地取得公开可访问音轨，截取 60–90 秒，分别生成原声、改前神经模式与修复后输出；不把这段未获再分发许可的音频加入仓库素材清单。

改前模式使用生产处理器重放 90%/16 kHz 干声混合，先与 2026-10-24 的历史 `clean-0` 输出核对，逐采样最大差为 0。修复后版本由指定一加实际执行 PCM16 事务生成，与桌面同一生产 Kotlin 输出的 RMS 差为约 `1.40e−5`。三个版本统一衰减约 12 dB并对齐固定延迟，没有逐文件峰值归一化；比较时只开人声增强，避免峰值保护和声道修复干扰。

该真实片段的 9 kHz 高通后能量，相对原声由改前约 −21.53 dB 变为修复后约 0 dB。它支持“原声高频被删掉”的诊断，不等于主观听感已经验收。原声没有独立干净人声参考，不能为该片段编造 SI-SDR/STOI。

简单试听页位于 worktree `captures/audio-user-sample-20261025/index.html`；只含“原声 / 改前的人声增强 / 修复后的人声增强”三个按钮，支持同位置切换。一加 `Download/BIL-Voice-Comparison-20261025/` 有中文命名的五个 WAV 与一份说明，其中修复后来自该机实际输出；六个文件均核对 SHA-256。应使用系统文件/音乐播放器试听，避免再次经过 B 站处理。

## 回归结果与取舍

49 项原固定输入哈希不变。前一版输出与耗时保存在 `captures/audio-benchmark/history/20261024/`；本轮逐项结果见 [新旧结果 JSON](audio-rescue-feedback-results-20261025.json)。不能把旧的 [首次神经版本成绩](audio-rescue-benchmark.md) 当成当前强度的成绩。

| 样本 | SI-SDR：改前 → 当前 | STOI：改前 → 当前 |
| --- | --- | --- |
| 干净讲话 0 | 25.34 → 28.65 dB | 0.9938 → 0.9964 |
| 干净普通话 | 22.87 → 25.94 dB | 0.9879 → 0.9945 |
| 普通话，居中 BGM 同能量 | 5.66 → 4.32 dB | 0.8310 → 0.8120 |
| 普通话，居中 BGM 比人声高 5 dB | 1.49 → −0.57 dB | 0.7743 → 0.7424 |
| 单独降噪：宽带底噪 | 15.52 → 15.52 dB | 0.9520 → 0.9520 |

保留原声和减轻模型强度使干净讲话损伤减少，但困难 BGM 的抑制力度下降；两者都应展示。峰值保护和自动补耳未改变算法，原回归行为保持。

一加 49 项测试 238.26 秒、用户实际 30 秒片段测试 19.86 秒，均 `OK (1 test)`。模型样本每 20 ms 块平均耗时 9.59–13.90 ms，P99 为 19.69–32.34 ms，最大单块 40.21 ms；均通过既有平均 16 ms 门槛，不代表每块都在 20 ms 内。两个测试还执行了轨道音量 0 的真实 AudioTrack 暂停/flush/恢复；没有改系统音量。

Debug APK、AndroidTest APK、3991 项 JVM 测试（3990 通过、1 项既有跳过）与快速 Lint 通过，原 3 项错误基线不变、260 警告；未运行完整 Lint。新增回归覆盖 10/16 kHz 原声保留、强抑制时高频保留、独立降噪的高频嘶声抑制，原有反相和部分写入回滚测试继续通过。最终检查日志为 `captures/audio-benchmark/build-feedback-final-20261025.log`。

一加 UI 复测截图为 `captures/audio-device-20261024/feedback-{before,after-top,after-bottom}.png`，顶部和滚动到底的说明完整。覆盖安装后冷启动宿主，授权正常、九个音频 Hook 就绪；最终按用户原有配置保留峰值保护与自动补耳开启，降噪与人声增强关闭，未以这次关闭状态的宿主日志冒充神经处理生效证据。手机回到用户指出的视频暂停页。重新开启人声增强仍需按界面说明重启宿主。

用户打开该实际视频的本地三版试听页后，于 2026-10-25 回复“确实是改好了”，确认本次修订的试听改善。该记录来自用户反馈，助手没有自行宣称完成人工耳听验收。
