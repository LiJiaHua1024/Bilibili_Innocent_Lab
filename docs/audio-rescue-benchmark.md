## 测试集

四段真实讲话：Microsoft DNS 2020 测试集 `clean_fileid_0/101/102`，以及 WeNet 固定版本中的 AISHELL-1 普通话测试资源。伴奏为 Kevin MacLeod 的 *Vibe Ace*（CC BY 3.0），经 librosa 官方素材站分发。下载只取短样本，固定 URL、提交、大小、SHA-256 和来源许可；不提交数据集音频。

固定 seed `20261024`，48 kHz、双声道，不逐段归一化，保留独立干净人声与干扰参考。覆盖：

- 干净讲话、干净讲话经过峰值保护，检查正常字头和音色的损伤。
- 人声/音乐能量比 +5、0、−5 dB，**音乐与讲话同时居中**；分别测试仅人声增强和叠加峰值保护。
- 宽立体声音乐、偏侧人声、反相人声，检查声像与相消问题。
- 仅左耳、仅右耳，包含讲话停顿。
- 50/60 Hz 与 100/120 Hz 电流谐波、+5 dB 宽带底噪、带噪停顿。
- 第 4 秒突然加入 25 ms 或 500 ms 的强声，前面是正常讲话。

这是“真实讲话/音乐 + 构造干扰”的可重复回归集；爆音不是从真实 B 站事故片段截取。只有四段讲话、一首音乐，不能据此推断所有音源。后续遇到真实坏视频，应记录时间点和配置追加本地回归。

## 修订及效果

旧版的窄频段/中侧滤波对居中 BGM 几乎没有分离能力，反而损伤讲话。修订版使用随包 GTCRN/DNS3 语音模型：16 kHz、512 点 FFT、256 点 hop，推理一次共享复数掩码再作用于原左右频谱。相消频点选择实际耳作参考；不把两耳分别推理的耗时翻倍。语音降噪保留 25% 干声，人声增强保留 10% 干声；同时开启时只处理一次。模型无网络请求，原生库及模型均校验固定大小与哈希。模型约 535 kB，两个 ARM ABI 的 ORT 原生库合计约 58 MB（未压缩）；安装包体积显著增加。

以下是**一加实际输出**。SI-SDR 越大代表相对干净参考的人声失真/干扰更少；它对整体增益不敏感，不是直接测得的“BGM 衰减”。STOI 是可懂度代理指标，不等于人工听感评分。模型固定延迟实测 1582 帧（32.96 ms）；各版本使用相同源时间区间计算，原始输出仍保留延迟。

| 样本 | 原始 SI-SDR → 修订版 | STOI：旧版 → 修订版 |
| --- | --- | --- |
| 普通话，居中 BGM，人声高 5 dB | 5.05 → 9.90 dB | 0.832 → 0.874 |
| 普通话，居中 BGM，同能量 | 0.06 → 5.66 dB | 0.767 → 0.831 |
| 普通话，居中 BGM，音乐高 5 dB | −4.92 → 1.49 dB | 0.675 → 0.774 |
| 宽带底噪 | 5.01 → 15.52 dB | 0.929 → 0.952 |
| 电流谐波 | 5.15 → 10.49 dB | 0.993 → 0.985 |

四段讲话 × 三档居中 BGM，在仅人声增强模式下，SI-SDR 相对输入提升 3.24–9.45 dB。叠加峰值保护时提升 1.40–9.29 dB；限幅也会改变讲话峰值，因此保真指标和仅增强不同。电流声的 STOI 比旧陷波方案略差，不能把所有指标都描述为提升。

峰值保护的相对阈值由 3.5 倍基线/最低 0.12 调整到 8 倍/最低 0.25，绝对 0.5 上限不变，减少自然字头被误压。25 ms、500 ms 突发样本前约 20 ms 的实际衰减分别为 10.73、9.05 dB，整段输出采样峰值分别为 0.315、0.309；旧版压得更深（17.10、15.42 dB），但正常讲话损伤更明显。例如第一段干净讲话经过限幅的 STOI 从旧版约 0.907 提升至 0.980。限幅后仍会听到强声，不应解释为完全消音。

自动补耳在持续不平衡 200 ms 后平滑接入，并跨讲话静音保持；原来每次停顿后重新等待的缺陷已修复。左右缺声样本从第 1 秒以后，左右差 RMS 由旧版 0.0117 降为 PCM16 下两耳相同（指标噪声地板 1e−10）。初始检测仍有延时，不会把所有短暂声像移动都改成单声道。

干净讲话经过模型的 STOI 为 0.985–0.994，原始为 1.000；个别 +5 dB BGM 样本也略有可懂度退化。模型会改变音色，不能无损提取任意人声，歌声和纯音乐建议关闭。固定延迟不增删帧，flush/stop 重置窗口；流结束时没有追加 drain，最后约一个窗口可能被截去。

## 一加性能与宿主接入

只操作用户指定的有线 `13a7a291`。ROM 自报 OnePlus PJZ110 / Android 16（API 36），底层平台为 MSM8998，CPU 上限约 1.90/2.45 GHz。LSPatch JingMatrix 1.2（487）/ API 102，哔哩哔哩 9.13.0（9130500）。这些耗时代表该机当前环境，不能按 ROM 型号当作新旗舰成绩。

- `renderCorpusAndExerciseAudioTrack` 跑完 49 项，224.37 秒，`OK (1 test)`；检查原输入不变、帧数不变、有限输出和峰值保护边界。另通过轨道音量 0 的真实 AudioTrack 暂停/flush/恢复，未调整系统音量。
- 模型样本每个 20 ms 块平均处理 8.70–12.61 ms；各样本 P99 为 15.99–32.92 ms，最大单块 40.48 ms。平均保留 20% 余量的 16 ms 门槛全部通过，**不代表每个块都小于 20 ms**。未开启模型的基本处理平均约 0.7–0.9 ms。
- 初版双耳独立模型在该机平均约 19–20 ms，未通过预算；共享掩码、单线程 XNNPACK 和预热后达到上述结果。未通过的原始记录保留。
- LSPatch 连接曾丢失，宿主因配置同步未完成拒绝启动授权。管理器重连并发布后，provider 正常授予，未改条款门控、未直接改授权偏好。主进程日志确认九个 Hook 已安装，实际 48 kHz 双声道 PCM16 写入含 `neural=true`，输入/输出均非静音。独立设备测试不被当作宿主加载证明。
- 同一固定视频 `BV1vFnB6JEje` 实测暂停/恢复、从约 1 分半拖到约 6 分半、三轮全屏并返回。每轮截图确认 2160×1080 / 1080×2160，操作后为 PLAYING。
- 初始轨道 547 从创建到首次暂停约 94 秒，AudioFlinger 欠载计数为 0。拖动和重新打开视频后的轨道 550 起始记录为 1920 帧（40 ms）；后续 45 秒保持 1920。继续播放至片尾自动切到下一集后，同一复用轨道累计到 83512 帧（约 1.74 秒）；没有换集前紧邻采样，不能精确归因。重新从固定视频开头播放，轨道 551 在约 285 秒源帧推进内五次采样均为 0（中间三次间隔各约 45 秒），这段连续播放未见供给不足。缓冲 7688 帧（约 160 ms）。不能称作所有操作零欠载，换集瞬间仍有未归因的等待，也未做小时级续航、温升或蓝牙路由验收。
- 采集区间未发现本轮宿主崩溃、ANR 或音频处理停用。系统媒体音量保持原来的 0 / 静音，方向锁保持 `0/0`。最终配置为峰值保护 + 自动补耳 + 人声增强（已包含降噪），单独降噪关闭；默认安装设置仍全关。

当前源码已通过 Debug APK、AndroidTest APK、全部 3988 项 JVM 测试（3987 通过、1 项既有跳过）、快速 Lint（260 警告、0 未基线错误；原 3 项错误基线未动）。没有运行完整 Lint。检查后只有说明性注释、评估脚本与文档变动，没有重复构建。

## 试听与证据

工作区 `captures/audio-benchmark/index.html` 可同位置切换原始/旧版/桌面修订版/一加输出/干净参考，并显示逐项指标。全部预览统一衰减约 12 dB，不逐文件峰值归一化；可选人声投影增益匹配只用于语音比较。连续 A/B 文件为原始、0.7 秒停顿、一加输出，已补偿固定模型延迟。

一加 `Download/BIL-AudioLab-20261024/` 已放入全部 49 个 A/B WAV、说明和来源许可。用系统文件/音乐播放器播放这些文件，不会再次经过只 Hook B 站的处理器。优先听 `voice-only-center-zh-+0dB-AB.wav`、`voice-only-center-zh--5dB-AB.wav`、`broadband-hiss-AB.wav`、两项 `sudden-burst` 和 `clean-zh-AB.wav`，分别判断音乐遮盖、底噪、突发声与音色损伤。

助手没有进行人工耳听；金属音、抽吸感、吞字和自然度仍需用户通过 A/B 判断，不能用指标宣称主观验收。当前结果说明在这组可复核条件下已有实质改善，并给出了局限。
